# JT1078 二进制帧结构（参考）

> 本目录下的 Python 模拟器只构造最小可用的帧；这里给出**完整**协议结构供深入参考。

## 帧格式

```
| SYNC (1B) | 消息 ID (2B) | 体属性 (2B) | 手机号 (6B) | 序号 (2B) | 总包 (2B) | 包序号 (2B) | 保留 (6B) | CRC (2B) | BODY (NB) | SYNC (1B) |
```

总长度 = 25 + body 长度

字段：
- SYNC = `0x7E`
- 消息 ID：大端 16 位
- 体属性：bit15 = 分包标志；bit14..bit10 = 加密方式；bit9..bit0 = body 长度
- 手机号：6 字节 BCD
- 序号：1~65535
- 总包 / 包序号：分包时使用，单包填 1
- CRC：从消息 ID 开始到 body 结束的 CRC-ITU

## 转义规则

为防止 0x7E 在 body 中出现，做如下转义：
- `0x7E` → `0x7D 0x5E`
- `0x7D` → `0x7D 0x5D`
- `0x01` → `0x7D 0x21`（某些实现）
- `0x02` → `0x7D 0x22`（某些实现）

## 关键消息 ID

| ID | 名称 | 方向 |
|----|------|------|
| 0x0100 | 终端注册 | 上行 |
| 0x0101 | 注册应答 | 下行 |
| 0x0002 | 心跳 | 上行 |
| 0x0001 | 通用应答 | 双向 |
| 0x0102 | 实时音视频 | 双向 |
| 0x0800 | 录像回放请求 | 下行 |
| 0x0801 | 录像回放应答 | 上行 |
| 0x0802 | 录像下载 | 下行 |
| 0x9201 | 录像列表查询 | 下行 |
| 0x8300 | 文本信息下发 | 下行 |
| 0x1006 | 紧急报警 | 上行 |
| 0x1007 | 超速报警 | 上行 |
| 0x1008 | 疲劳驾驶 | 上行 |
| 0x1009 | 危险驾驶 | 上行 |
| 0x100A | GNSS 故障 | 上行 |
| 0x100B | GNSS 天线断开 | 上行 |
| 0x0200 | 位置上报 | 上行 |
| 0x0005 | 重传请求 | 下行 |

## 终端注册 (0x0100) body 结构

```
| 省 ID (2B) | 市 ID (2B) | 厂商 ID (11B) | 型号 (30B) | 终端 ID (30B) | 车牌颜色 (1B) | 车牌 (12B) |
```

总长 76 字节。

## 通用应答 (0x0001) body 结构

```
| 应答流水号 (2B) | 应答 ID (2B) | 结果 (1B) |
```

## 实时音视频 (0x0102) body 头部

```
| 帧类型 (1B: 0=P帧, 1=I帧, ...) | 分包标记 (1B) | 视频分包 (1B) | ...
```

## 模拟器支持

`mock/tools/jt1078-terminal/jt1078_terminal_mock.py` 当前支持上行消息的**最小可用实现**：
- 0x0100 注册 → 0x0101 应答
- 0x0002 周期性心跳
- 0x0200 周期性位置
- 0x1006-0x100B 报警（手动）
- 0x0801 录像列表应答

**未实现**：实时音视频 0x0102 上行（需要真实 H.264/H.265 流）；录像回放 0x0800 控制。
