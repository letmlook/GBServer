## 目标 Linux 部署

1. 按 `DEPLOYMENT_GUIDE.md` 配置设备可达的 `GBSERVER_SIP_ADVERTISE_IP`、独立
   JWT 密钥及 SIP 密码；检查 SIP 端口、ZLM 收流端口池与主机防火墙。实际值以
   目标网络为准，不沿用历史开发机 IP。
2. 在目标 Linux 按部署指南启动所选 Compose 配置，记录 `docker compose ps`、
   后端与 ZLM 健康状态及镜像摘要。确认 ZLM 的 host 网络、Hook 和 RTP 端口池
   与目标部署一致。不要通过清空现有卷来准备验收。
3. 从使用者浏览器验证登录和页面加载；确认业务 HTTP 经过 GBServer，媒体地址
   指向浏览器可达的 ZLM。检查 WebRTC ICE 及媒体是否可达，记录协议和错误信息。

## 真实 GB28181 核心闭环

1. 在设备上设置平台地址、国标 ID、域及凭据，确认设备与平台网络相通。记录
   401 摘要挑战、注册成功、心跳及设备在线状态；检查目录同步后的设备和通道 ID。
2. 选中该通道启动直播，记录起流请求、流标识、ZLM 实际收流和浏览器可见画面；
   停止后确认设备收到对话内 BYE，平台不再保留该活动流和收流端口。
3. 建立覆盖当前时间的临时录像计划并关联通道，记录计划 ID、流标识、新录像
   记录 ID、文件大小及产生时间；停止计划后验证新文件可播放或下载，再清理本次
   临时计划。历史文件、仅 HTTP 200 或仅计划创建成功不能作为录像通过证据。
4. 选择设备支持的一项控制命令，记录请求、匹配的设备应答及页面/API 的结果。
   将“平台配置保存”“SIP 已发送”“设备执行成功/失败”“结果未确认”分别记录；
   不把 SIP 200 或发送成功当成设备执行成功。若设备不返回执行结果，记为未确认。
